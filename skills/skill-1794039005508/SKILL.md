# 轻量多平台发布闭环

## 总原则与输入
固定底线，不固定文章长相。读取任务上下文指定的唯一现行项目规则、最新有效策略卡和本轮有效授权；账号、素材来源、视觉、音乐、挂群、归档与汇报位置放在项目规则，不在技能或入职说明重复硬编码。冲突以用户最新明确要求为准，须能核对本人原文；真实缺口集中询问一次，已明确事项不机械复述再求确认。技能本身不是自动发布或站立授权，不越过外发规则。

**单一负责人：** 每批由一个执行负责人完成制作、交审、提交、查结果、归档和交付。其他角色按需提供素材、分析或审核意见，不并行提交或临时接管，不另加未经确认的门槛；执行中不插入无关工作。

**平台要求：** 图片数量、比例、原像素、实况支持、叠字及标题要求读取项目规则，不沿用旧批次或其他平台样式。附加项是否阻塞也读取项目规则，不把可选项升级成硬门，不自行降低明确必需项。

## 1. 复用策略，不逐帖重跑研究
读取策略卡的目标读者、内容方向、素材依据、禁区和能力版本。日常不每帖召回复盘角色、不等重复分析；标题按需复用「小红书标题研究与复用」，不增加已授权内容的重复审批。地域、任务价值、细节、真实反差只是可选机制，允许有素材依据的新角度，不要求每篇都有地域、悬念或预期差。未变化的已通过样式不重审。

## 2. 选材制作，内置一次去AI味
按本批需要核对原件、已发台账和相似性；历史不明跳过该素材，不因此无边界遍历全部历史。各号选明显不同角度，不只换同义词；标题、封面、素材一起查重。结构、长度和语气随内容、账号及读者变化，不强制钩子—痛点—方案—行动号召，不固定字数、段数、emoji数量或口头禅；遵守平台实际限制。制作时内置一次自然表达自检及必要改写，不新增审批角色、独立报告或多轮打分：
- 真实细节：只写有依据的动作、物件和问题，不为生动编台词、人数或氛围。
- 作者口吻：参考已认可原文的用词、判断和节奏，不机械复制口癖；自然不等于强行口语化，第一人称亲历须有依据。
- 具体动作和结果：写清谁做了什么、解决什么；没有数据或结果不补数字、效果或因果。
- 删除空泛套话：清除无信息的拔高、广告腔、机械排比、重复收尾；句式和标点只是检查信号，不设机械禁词表。
- 回读保真：不改变事实、原意、引用、范围和不确定性，不加假感受、错字或假亲历装真人，不承诺绕AI检测。
题文封面互相兑现，清除内部流程残留。账号、事实、版权、真实格式和授权不可擅自降级；表达结构可变，具体平台及项目要求只由现行项目规则确定。

## 3. 集中核验一次，授权内提交
核验真实账号ID及有效范围、排重、成品格式、题文、音乐权利及可用性、项目要求的挂群项、账号限制和有效授权。有授权且满足全部必需项才提交；无有效授权交待审包。本人批准只覆盖看到的版本、账号和范围；已有可核批准不重复要求批准，实质变化才重新交审。助手转述、历史记忆和项目文档不能替代本人授权。
新平台或格式先验单样本，缓存工具版本、适用范围、时间及证据，相关变化才重验。文档存在或能查群不等于发布或挂载可用。不拼来源字段、不绕校验、不向授权范围外发送。
提交前保存唯一提交意图和可核标识。超时或结果不明先只读核对原任务，禁止重复提交；单账号失效或受限隔离该账号，不绕过、不盲重试。全局服务故障停止后续账号并明确报告；不要为了继续而绕过校验。
用蚁小二批量提交时，具体落盘、防重和回执判定可复用「yxer-batch-publish-no-duplicate」。

## 4. 查结果、归档、轻记录
区分待审、已提交、处理中、成功、失败、受阻和结果未知。退出码正常或已启动不等于发布成功。平台成功证据、原素材已发状态读回核验、台账三项齐全才完成；归档失败只补归档不重发。每批记录账号、主题或标题、素材标识、策略版本、发布ID或链接、结果和异常，在项目指定位置汇报；缺少公开可见性验证时明确区分平台回执与前台可见。指标后续统一采，不逐帖写长复盘。

## 长任务与结果交付
长任务使用平台支持的后台任务完成通知，保存任务标识和证据路径，不把脱离管理的后台进程当成可自动续接的任务。完成通知到达后，必须读取真实退出码、错误输出和结果，再主动交付成功、失败、未知、卡点与下一步。启动后不能直接报完成；本地完成文件不等于通知已送达。
不新增定时催问或常驻轮询来掩盖漏接。通知机制不能确认时如实说明；下次处理前先核现有任务、进程及提交记录，不整批重跑。不得承诺平台通知一定唤醒。

## 独立复盘与排障
按已确认周期系统复盘，异常或新增有效数据增量更新，不自行建定时。策略卡分事实、假设和下轮测试；主题、标题、封面、格式分开标注，曝光、点击、互动、真实转化分开看。补同账号普通及低表现基线与相同观察窗；高点击筛选表不代表全量，观看除以曝光不擅代官方点击率，相关性不作因果，没有新证据不强造规则。
技术排障移出日常链路，记录具体缺口、证据和下一步；没有新证据不循环同一失败，不在正式入口未证实时批量制作。只隔离受影响账号或格式，其余满足必需项且有有效授权者独立推进；全局服务故障除外。格式降级、扩大范围、新承诺或权限变化另获批准；技能不能补齐未打通能力。采用已验收的适用入口或模板，新批次核适用性并保留回滚依据，不把单批补丁当通用能力。
